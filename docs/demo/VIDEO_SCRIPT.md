## 0:00–0:25 — The execution gap

“A deadline tells a student when work is due, but not when to start, which steps
depend on others, or how to recover when the week changes. StudyFlow turns
assessments into executable work and keeps that plan useful after life changes.”

Show the cover and loop; move to the browser promptly.

## 0:25–1:10 — Reset, generate and explain

Demo Reset → confirm → Generate Plan → wait → expand task actions.
Point to actual minutes and Requires links for the presentation.

“Here we use realistic Canvas and calendar mocks with validated preparation
templates. StudyFlow also supports optional model-assisted decomposition.
Presentation, exam and coding work each have a preparation workflow. The
scheduler fits these steps around study time and hard commitments.”

## 1:10–1:40 — Observe progress

Mark presentation requirements Complete, then materials Missed.

“These buttons demonstrate student progress reports. Materials are a prerequisite
for speaker notes and rehearsal, so a missed report triggers a check of that
unfinished chain. A future slot may still be valid; the system does not move work
just to create a visible change.”

Show the actual result. Never promise movement at this step.

## 1:40–2:35 — A real calendar conflict

Read the materials row's current start/end. Add Extra lecture, Hard, over that
exact interval using the calendar form. Submit once and wait.

“Now an extra lecture occupies the time planned for materials. The hard block
cannot move, so StudyFlow recalculates affected work. Here are the old and new
times. Completed work and unrelated valid placements are preserved where
possible. If capacity runs out, the task stays visible with a specific reason.”

Show one Moved pair and the completed Preserved item. Point out dates/timezone
for cross-day moves. Read an Unscheduled message if one appears.

“A new assessment enters the same workflow: normalize, decompose, schedule and

## 3:10–3:30 — Reset

Demo Reset → confirm → show empty tasks and Generate Plan again.

“Reset restores the startup state for another run. If a saved operation needs
a refresh, Retry reads state without submitting the action again.”

Show slide 6 or 9, then the closing slide.

“Python, FastAPI and Pydantic enforce shared contracts; React and TypeScript show
the result. The agent prepares work, deterministic constraints govern the schedule,
